## 一、 前言与硬件基准画像

### 1.1 硬件画像与并发负载模型
本调优方案以经典的移动端老旧平台为测试与基准画像：
- **中央处理器 (CPU)**：Intel Core i5-4210H (Haswell 架构，双核四线程 2C4T，基准 2.9GHz / 睿频 3.5GHz)。
- **核心显卡 (iGPU / GPU 0)**：Intel HD Graphics 4600（共享系统内存作为动态显存，集成 Intel QuickSync Video 专用硬解模块）。
- **独立显卡 (dGPU / GPU 1)**：Nvidia GeForce GTX 960M (Maxwell 架构，**仅 2GB GDDR5 独立显存**)。
- **系统内存 (RAM)**：16 GB DDR3L。
- **并发挂机软件拓扑**：
  1. **网易 MuMu 12 模拟器**：运行《碧蓝航线》，需要 3D 渲染支持；
  2. **Thorium 浏览器**：后台播放 1080p / 4K 60fps 高清直播或视频；
  3. **网易云音乐**：后台常驻音频播放；
  4. **Alas 客户端**：Python 自动化调度器（图像识别、模板匹配与 OCR）+ Electron/Vue 前端界面。
- **系统虚拟内存压力**：常态虚拟内存置换用量达到 **15.8 GB**，系统总提交内存（Commit Charge）高达 **31 GB**。

### 1.2 极端场景下的三大系统性痛点
1. **显存击穿与 WDDM 驱动重置崩溃 (`LiveKernelEvent 141`)**  
   GTX 960M 仅有 2GB 独立显存。在默认未分流状态下，MuMu 12 独占约 800MB~1.1GB 显存，若此时 Thorium 浏览器硬解高清视频或 Electron 界面同样被分配给独立显卡，独显显存瞬间被刺穿并溢出至宿主机系统内存。WDDM 内存管理器在高频显存/内存置换期间出现超过 2 秒的调度等待，直接触发 Windows TDR (Timeout Detection and Recovery) 机制，显卡驱动被强行重置，导致模拟器 Direct3D 交换链崩溃闪退。
2. **虚拟内存置换颠簸 (PageFile Thrashing 与磁盘 100% 假死)**  
   当系统常态虚拟内存需求高达 15.8GB 时，如果 Windows 分页文件（PageFile）设置为动态伸缩，或者分页文件散落在机械硬盘（HDD）上，机械硬盘高昂的寻道延迟（10~15ms）和有限的随机读写吞吐，会在发生硬缺页时瞬间导致磁盘 I/O 饱和（100% 利用率），引发整机假死长达 10~30 秒，进而导致 Alas 心跳超时。
3. **双核四线程 CPU 算力竞逐与发热降频**  
   i5-4210H 仅有 2 个物理核心。若为模拟器分配 3~4 个核心，宿主机将丧失足够的调度算力，导致 Python 图像识别延迟急剧增加。若 MuMu 12 未能启用原生的 NemuIPC 共享内存截图（而是退化为 ADB 管道），截图过程将消耗高达 25% 的 CPU 算力，持续高负荷会瞬间冲破 Haswell 笔记本 85℃ 的散热阈值，引发硬件级降频（Thermal Throttling）。

## 三、 分步配置操作详解

### 1. Windows 图形首选项硬分流

Windows 10 (2004 以后版本) 与 Windows 11 提供了操作系统内核级的 GPU 调度首选项，其优先级高于应用程序自身的默认行为。

#### 1.1 图形设置界面操作步骤
1. 打开 Windows **“设置”** -> **“系统”** -> **“屏幕”**（或“显示”）。
2. 下拉到底部，点击 **“显示卡”**（Windows 11）或 **“图形设置”**（Windows 10）。
3. 在“添加应用”下拉菜单中选择 **“桌面应用”**，点击 **“浏览”** 按钮。
4. **添加独立显卡进程**：
   - 浏览并定位到 MuMu 12 安装路径：`...\MuMuPlayer-12.0\shell\MuMuPlayer.exe`（若有多开组件，建议一并添加 `MuMuNxDevice.exe`）。
   - 添加后，在列表中点击该应用，选择 **“选项”**。
   - 选择 **“高性能”**（其下方会明确标注你的独立显卡名称，例如 *NVIDIA GeForce GTX 960M*），点击 **保存**。
5. **添加核心显卡进程**：
   - 浏览并添加 Thorium 浏览器：`C:\Users\<用户名>\AppData\Local\Thorium\Application\thorium.exe`。
   - 点击 **“选项”**，选择 **“节能”**（其下方会明确标注集成核显名称，例如 *Intel(R) HD Graphics 4600*），点击 **保存**。
   - 浏览并添加 Alas 桌面启动程序：`<Alas路径>\AzurLaneAutoScript.exe`。
   - 点击 **“选项”**，选择 **“节能”**，点击 **保存**。

#### 1.2 注册表底层规范与数据验证
上述图形设置在注册表中的保存路径为：  
`HKEY_CURRENT_USER\Software\Microsoft\DirectX\UserGpuPreferences`

注册表键值规范如下：
- **键名 (Name)**：可执行文件的完整绝对路径（`REG_SZ` 字符串）。
- **键值数据 (Data)**：
  - `GpuPreference=1;`：强制指定为 **节能 (Power Saving / 集成核显)**；
  - `GpuPreference=2;`：强制指定为 **高性能 (High Performance / 独立显卡)**；
  - `GpuPreference=0;`：由 Windows 自动决定。

您可以打开注册表编辑器（`regedit`）导航至该路径，确认以下项已正确定向：
```registry
[HKEY_CURRENT_USER\Software\Microsoft\DirectX\UserGpuPreferences]
"E:\\Program Files\\Netease\\MuMuPlayer-12.0\\shell\\MuMuPlayer.exe"="GpuPreference=2;"
"C:\\Users\\Lemony\\AppData\\Local\\Thorium\\Application\\thorium.exe"="GpuPreference=1;"
"D:\\Computers\\AIDevelop\\Tools\\Games\\Alas\\AzurLaneAutoScript.exe"="GpuPreference=1;"
```

### 2. Nvidia 控制面板防范设置

为了避免 Nvidia 驱动程序全局覆盖 Windows 图形首选项，必须校准 Nvidia 控制面板。

1. 在桌面空白处单机鼠标右键，打开 **“NVIDIA 控制面板”** (`nvcplui.exe`)。
2. 在左侧树状导航中展开 **“3D 设置”** -> 点击 **“管理 3D 设置”**。
3. **全局设置检查（至关重要）**：
   - 切换到 **“全局设置”** 选项卡。
   - 找到 **“首选图形处理器”**，必须保持为 **“自动选择”** 或 **“集成图形”**。
   - **严禁**在此处全局指定为“高性能 NVIDIA 处理器”，否则将导致所有后台进程无脑挤占 GTX 960M 显存。
4. **程序设置精细化验证**：
   - 切换到 **“程序设置”** 选项卡。
   - 选择或添加 `MuMuPlayer.exe`，确保其首选图形处理器为 **“高性能 NVIDIA 处理器”**。
   - 确认 `thorium.exe` 未被单独强制指定为独显。

### 3. MuMu 12 性能参数与保活关闭 (NemuIPC 前置条件)

MuMu 12 是挂机过程中的渲染主体，其设置直接决定系统发热量与 Alas 截图管道的生死。

#### 3.1 性能与显示推荐配置
打开 MuMu 12 主界面右上角的 **“设置中心”**：
1. **性能设置**：
   - **显卡渲染模式**：选择 **“DirectX 模式 (DirectX 11)”**。GTX 960M 为 Maxwell 架构，Nvidia 在 DX11 驱动层做了数十次专项迭代，稳定性远胜 Vulkan，能大幅降低因着色器编译超时引发的 TDR 驱动崩溃。
   - **性能设置**：选择 **“自定义”**。
     - **CPU**：设置为 **2 核**（严禁分配 3 或 4 核！必须保留剩余 2 个逻辑线程供宿主机调度 Python 图像识别算法与 QuickSync 视频硬解）。
     - **内存**：设置为 **3072 MB (3 GB)**（既满足碧蓝航线资源载入，又防止 Android 虚拟机无休止向宿主机申请物理 RAM）。
2. **显示设置**：
   - **分辨率设置**：严格选择 **“1280×720 (16:9)”**，DPI 设为 **240**。
     > **注意**：Alas 的全部坐标网格与图像模板识别均以 720p 为基准，**严禁为了降温下调此分辨率**，否则将导致脚本坐标偏移与界面匹配失败。
   - **帧率设置**：将帧率上限拉杆锁定至 **30 FPS**，并确保 **关闭“开启高帧率模式”**。
     - 相比 60 FPS，锁定 30 FPS 可以让 GTX 960M 的 3D 渲染功耗下降约 35%~45%，核心温度下降 6~10℃；同时 30 FPS 完全能够满足 Alas 每秒 1~3 次的采样识别，杜绝 20 FPS 下偶发的过场丢帧。

#### 3.2 深度剖析：为何必须彻底关闭“后台挂机保活”？
在 MuMu 12 的 **“运行与保活”** 设置分类中，有一项 **“后台挂机保活（降低刷新率保活）”**，**必须将其彻底关闭**！

**技术原理剖析**：
1. **NemuIPC 的极速原理**：  
   Alas 支持网易模拟器原生的 NemuIPC 共享内存捕获技术。MuMu 12 核心附带了动态链接库 `external_renderer_ipc.dll`，该库通过 Direct3D 共享纹理句柄与系统命名共享内存，直接将 Android 内部渲染输出的 1280×720 32bpp 帧缓冲区传递给 Alas。
   - **单次截图耗时**：仅需 **5 ~ 15 毫秒**；
   - **宿主机 CPU 占用**：**接近 0%**。
2. **保活机制的致命破坏**：  
   当开启“后台挂机保活”后，一旦模拟器窗口最小化或失去焦点，MuMu 的渲染管线为了省电，会主动切断常规的 Direct3D SwapChain（交换链）呈现管线，转而使用离屏降频占位图。此时：
   - `external_renderer_ipc.dll` 无法触发画面呈现事件，内部 RPC 通信中断；
   - 产生底层异常报错：`nemu_capture_display cannot find rpc connection` 或系统错误代码 `1722 / 1726`；
   - 读取出来的图像数据持续全黑或完全静止；
   - Alas 判定截图超时，**自动退化为最原始的 ADB 截图管道**（通过 ADB 传输截屏二进制流）。
   - ADB 管道不仅单次截图耗时暴增至 150~400 毫秒，还会导致宿主机双核 CPU 占用飙升 25% 以上，引发剧烈发热与卡顿。
3. **配置文件核对**：  
   在多开配置目录 `<MuMuPath>\vms\MuMuPlayer-12.0-{index}\configs\customer_config.json` 中，确保以下键值存在并为 `false`：
   ```json
   "customer.app_keptlive": false
   ```

### 4. SSD PageFile 虚拟内存规整

在 7×24 小时高负荷挂机下，系统提交内存高达 31GB，物理内存仅 16GB，虚拟内存置换用量常态达到 15.8GB。配置不当的 PageFile 会成为导致整机卡死的元凶。

#### 4.1 机械硬盘换页颠簸危害
如果系统分页文件被设置在机械硬盘（HDD）上，或者设置为系统动态伸缩：
- 当内存发生硬缺页置换时，HDD 的机械磁头在 10~15ms 的高延迟下反复寻道；
- 瞬间引发系统磁盘队列深度爆表，资源管理器显示磁盘利用率 **100%**；
- 整个 Windows 调度器发生颠簸（Thrashing），系统在长达 10~30 秒内无法响应键鼠操作与脚本心跳。

#### 4.2 固态硬盘固定尺寸配置指引
必须将分页文件**全部集中在高速固态硬盘（SSD）**上，并设置固定尺寸：
1. 按下快捷键 `Win + R`，输入 `sysdm.cpl` 并回车，打开 **“系统属性”**。
2. 切换到 **“高级”** 选项卡 -> 点击“性能”区域的 **“设置”** 按钮。
3. 在弹出的“性能选项”对话框中，切换到 **“高级”** 选项卡 -> 点击“虚拟内存”区域的 **“更改”** 按钮。
4. **取消勾选** 最上方的 **“自动管理所有驱动器的分页文件大小”**。
5. **移除机械硬盘分页**：
   - 逐个点击所有机械硬盘（HDD）盘符（如 D:、E: 等）；
   - 选择 **“无分页文件”**，并点击 **“设置”** 按钮。
6. **配置固态硬盘（SSD，通常为 C: 盘）固定分页**：
   - 选中 SSD 所在的驱动器盘符；
   - 单选 **“自定义大小”**：
     - **初始大小 (MB)**：输入 `16384`（16 GB）；
     - **最大值 (MB)**：输入 `20480`（20 GB）；
   - 务必点击 **“设置”** 按钮（确认驱动器列表中显示 `16384 - 20480`）。
7. 连续点击“确定”保存，并根据提示重启电脑使虚拟内存分配生效。

> **收益说明**：固定分页文件尺寸彻底消除了 Windows 在运行时频繁申请磁盘簇、扩展文件尺寸带来的文件系统级锁死；配合 SSD 数万 IOPS 的随机吞吐，硬缺页置换可在微秒级完成。

### 5. Windows TDR 注册表超时加固

Windows 显卡驱动超时检测与恢复（TDR）机制默认将超时阈值设为 **2 秒**。对于 GTX 960M 这类老旧显卡，在游戏大版本更新资源载入、多任务突发换页时，GPU 调度队列极易出现瞬间超过 2 秒的延迟，导致 Windows 误判显卡硬件死锁并强行杀掉驱动，引发黑屏与 `LiveKernelEvent 141`。

#### 5.1 加固注册表参数定义
- 目标注册表路径：  
  `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\GraphicsDrivers`
- 关键参数：
  - `TdrDelay` (REG_DWORD)：从默认 2 秒放宽至 **8 秒** (`0x00000008`)。
  - `TdrDdiDelay` (REG_DWORD)：DDI 驱动接口超时同步放宽至 **8 秒** (`0x00000008`)。
  - `TdrLevel` (REG_DWORD)：保持为 **3** (`0x00000003`，即 `TdrLevelRecover`)。

> **安全红线警告**：  
> **严禁将 `TdrLevel` 设置为 0 (`TdrLevelOff`)！**  
> 设为 0 会彻底关闭 Windows 的显卡超时检测。一旦显卡驱动发生死锁，系统将无法自愈恢复，直接导致整机蓝屏或硬死机。保持为 3 并在 8 秒超时时触发恢复，是最为科学稳健的防灾设计。

#### 5.2 一键导入与恢复脚本
Alas 已在 `deploy/optimize/` 目录下预置了经过严格语法审计的注册表导入与恢复脚本：

- **一键启用 8 秒超时加固**：
  直接双击运行工程目录下的：  
  `deploy/optimize/enable_tdr_delay_8s.reg`  
  在弹出的 UAC 提示与注册表写入确认窗口中点击“是”。
- **一键恢复系统默认设置**：
  若后续需要还原 Windows 默认的 2 秒行为，直接双击运行：  
  `deploy/optimize/restore_tdr_delay_default.reg`  
  该文件使用标准的减号语法 (`"TdrDelay"=-`) 清理自定义项，安全无残留。

### 6. 系统电源计划与散热优化

1. **电源计划设为“平衡”**：
   - 打开“控制面板” -> “硬件和声音” -> “电源选项”；
   - 选用 **“平衡”** 计划，点击右侧 **“更改计划设置”** -> **“更改高级电源设置”**。
2. **压制 85℃ 过热睿频（关键技巧）**：
   - 在高级电源设置列表中展开 **“处理器电源管理”** -> **“最大处理器状态”**；
   - 将“接通电源”时的数值从 `100%` 改为 **`99%`**。
   - **效果**：Windows 将禁用 Intel CPU 的主动激进睿频（Turbo Boost），将 i5-4210H 的运行频率锁死在基准频率 2.9GHz。对于 Haswell 移动处理器，这一步可直接使 CPU 满载温度暴降 8~12℃，彻底远离 85℃ 热降频线，且 2.9GHz 算力足以流畅跑满 Alas 调度。
3. **关闭 USB 选择性暂停**：
   - 在高级电源设置中展开 **“USB 设置”** -> **“USB 选择性暂停设置”**，设置为 **“已禁用”**。
   - 防止系统在无人操作进入节能状态时关闭 USB 管道，导致与模拟器的 ADB 通信无故中断。

## 四、 运行状态验证方案

配置完成后，请启动 MuMu 12、Thorium 浏览器（播放 1080p 视频）以及 Alas 挂机任务，按照以下步骤进行分工核验。

### 1. Windows 任务管理器分工校验

按下快捷键 `Ctrl + Shift + Esc` 打开任务管理器，切换到 **“性能”** 选项卡，观察 **GPU 0 (Intel HD Graphics 4600)** 与 **GPU 1 (NVIDIA GeForce GTX 960M)** 的负载分配：

| 进程名称 | 理想绑定的显卡 | 核心引擎负载 (Engine) | 专用显存占用 (Dedicated VRAM) | 共享显存占用 (Shared RAM) | 状态判定依据 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `MuMuPlayer.exe` | **GPU 1 (GTX 960M)** | **3D 引擎** (15% ~ 35%) | **700 MB ~ 1100 MB** | 0 MB ~ 100 MB | 独享独立显存，独占 3D 计算 |
| `thorium.exe` | **GPU 0 (HD 4600)** | **Video Decode 视频解码** (20% ~ 45%) | **0 MB** (绝对不得占用独显) | 200 MB ~ 500 MB (动态系统 RAM) | 核显硬解视频，完全释放独显显存 |
| `AzurLaneAutoScript.exe` | **GPU 0 (HD 4600)** | **3D / Desktop Window Manager** (1% ~ 5%) | **0 MB** (绝对不得占用独显) | 50 MB ~ 150 MB (动态系统 RAM) | WebUI 界面渲染隔离于核显 |

**判定标准**：
- **正常状态**：GPU 1 专用显存保持在 1.1GB 以下（距离 2GB 警戒线有 900MB 以上的安全缓冲）；GPU 0 负责视频解码；CPU 整体占用平稳在 30%~55% 之间。
- **异常状态**：如果发现 `thorium.exe` 出现在 GPU 1 上，或者 GPU 1 专用显存飙升到 1.8GB 以上，说明图形首选项未生效，请重新核对章节 [三.1](#1-windows-图形首选项硬分流)。

### 2. GPU-Z 与传感器指标核验
打开免费硬件监控工具 GPU-Z：
1. 选中 **NVIDIA GeForce GTX 960M** 页面，切换至 **“Sensors”**（传感器）选项卡。
2. 观察指标：
   - **Memory Used**：应在 800MB ~ 1100MB 之间波动。
   - **GPU Temperature**：在散热正常情况下应保持在 65℃~75℃ 之间。
   - **Performance Cap Reason**：不应长时间出现 `Thrm`（温度墙）或 `Pwr`（功耗墙）导致的剧烈降频跳动。

## 五、 常见故障排查手册 (FAQ)

### Q1: Alas 提示 NemuIPC 未生效，回退为 ADB 截图怎么办？
**排查四步法**：
1. **核对挂机保活设置**：  
   打开 MuMu 12 设置中心 -> “运行与保活”，确认“后台挂机保活”已彻底关闭。关闭后必须**重启模拟器**方能生效。
2. **检查 DLL 动态链接库完整性**：  
   确认 MuMu 12 安装目录下是否存在 `external_renderer_ipc.dll` 文件（常见路径位于 `<MuMuPath>\shell\sdk\` 或 `<MuMuPath>\nx_device\12.0\shell\sdk\`）。如果被杀毒软件误删，请在安全软件中设置白名单并修复安装。
3. **确认模拟器运行在独立显卡**：  
   NemuIPC 依赖 Direct3D 交换链。如果 MuMu 12 被误调度在集成核显上，可能会因为驱动版本或纹理句柄共享限制导致 NemuIPC 握手失败。
4. **检查 Alas 模拟器连接配置**：  
   在 Alas WebUI 的“设置” -> “模拟器设置”中，确认模拟器类型正确选择为 `MuMuPlayer12`，且多开序号与实际运行的模拟器实例严格一致。

---

### Q2: 挂机一段时间后屏幕黑屏数秒并恢复，伴随 LiveKernelEvent 141 错误？
**根因与处置方案**：
1. **事件本质**：  
   `LiveKernelEvent 141` 是 Windows 系统典型的显卡硬件或驱动超时恢复事件（TDR）。
2. **处置步骤**：
   - **第一步**：确认已成功双击导入 `deploy/optimize/enable_tdr_delay_8s.reg`，给老显卡足够的防抖缓冲。
   - **第二步**：检查独立显存占用。打开任务管理器确认是否有多余程序（如浏览器、壁纸引擎、视频播放器）误占了 GTX 960M 显存。
   - **第三步**：检查笔记本散热。GTX 960M 笔记本大多服役年限较长，若硅脂干涸或风扇积灰，核心温度一旦瞬时触碰 85℃~90℃ 会引发硬件级锁死断电保护，务必进行清灰与更换硅脂。
   - **第四步**：显卡驱动版本回退。对于 Maxwell 架构的 GTX 960M，最新的 Game Ready 驱动往往并未专门优化，推荐安装经典的稳定版驱动（如 Nvidia 472.12 WHQL）。

---

### Q3: 为什么挂机时整机卡死几十秒，磁盘利用率飙升至 100%？
**根因与处置方案**：
- 这属于典型的 **PageFile 磁盘颠簸 (Thrashing)** 现象。
- 请严格按照 [三.4 节](#4-ssd-pagefile-虚拟内存规整) 的指引：
  1. 彻底关闭所有机械硬盘（HDD）上的分页文件；
  2. 仅在固态硬盘（SSD）上设置固定初始大小（`16384 MB`）和最大值（`20480 MB`）；
  3. 严禁使用“系统管理的大小”，确保文件尺寸恒定，彻底阻断动态申请导致的磁盘假死。

---

### Q4: 能否把游戏内渲染分辨率降低至 1280×720 以下以降低负载？
**绝对不能！**
- Alas 的图像识别引擎、文字识别（OCR）、按钮定位与坐标换算，均严格按照 1280×720 (16:9) 分辨率下的像素坐标系进行标定。
- 若将模拟器分辨率改为 960×540 或更低，会导致图像模板尺寸失配、文字特征模糊以及点击坐标偏移，直接造成日常出击、换装与战斗结算全流程死循环。
- 若需进一步降低功耗，请通过**锁定 30 FPS 帧率**与**关闭处理器过热睿频**来实现，切勿改动 720p 分辨率。
